# Phase 8: 模型透传/解析双模式

## 设计

### 背景
不同模型需要不同的处理模式：
- **透传模式**：网关完全不解析请求/响应，直接代理到后端，插件不可用
- **解析模式**：网关解析请求内容，非阻塞发送给插件链，插件可干预结果

### 模型颗粒度配置
每个模型 YAML 配置新增 `mode` 字段：

```yaml
# 透传模式 - 直接代理到后端，不经过插件
id: gpt-4
type: chat
mode: passthrough
conn_config:
  base_url: "http://backend:8080"

# 解析模式 - 经过插件链处理
id: glm-ocr
type: ocr
mode: parsed
conn_config:
  base_url: "http://ocr-backend:8099"
```

### 透传模式流程
```
客户端 → POST /v1/{endpoint}
    → API Key 校验
    → 查找模型配置
    → mode == "passthrough"?
      → 直接代理到 conn_config.base_url + 原始路径
      → 返回后端原始响应
    → 不经过任何插件
```

### 解析模式流程（当前逻辑）
```
客户端 → POST /v1/{endpoint}
    → API Key 校验
    → 查找模型配置
    → mode == "parsed"?
      → 解析请求内容
      → 非阻塞发送给插件链
      → 调用后端
      → 插件链处理响应（替换/阻断/添加）
      → 返回结果
```

### 差异对比
| 维度 | 透传模式 | 解析模式 |
|------|----------|----------|
| 性能 | 高（零解析） | 较低（解析 + 插件） |
| 插件 | 不可用 | 可用（异步非阻塞） |
| 内容感知 | 无 | 完全感知 |
| 适用场景 | 标准 OpenAI 兼容模型 | 需要内容审计/过滤/增强的模型 |
